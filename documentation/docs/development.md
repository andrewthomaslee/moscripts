# Development

Needs Nix and [devenv](https://devenv.sh). The shell is the org shell from
external-systems/pkgs plus `org-pkgs/devenv/python`: an editable uv2nix
venv (`moscripts`, its four commands, pytest) importing straight from
`src/`, and the org's `uv`, `ruff` and `ty`.

```sh
devenv allow        # auto-activates the shell on cd (after `devenv hook`)
fmt                 # treefmt: Nix, shell, Markdown
check               # nix flake check
docs-build          # this site to ./result-docs; open index.html from disk
devenv up           # live docs on :8981, slides on :8982
```

## Layout

```
pyproject.toml uv.lock         the uv workspace (uv_build backend)
src/moscripts/                 the package; one module per command
tests/                         pytest
flake-parts/python.nix         settings for org-pkgs flakeModules.python
vm-tests/cli-smoke.nix         NixOS VM test of the installed package
documentation/                 this site and the deck
```

## Python loop

```sh
uv add httpx                   # or edit pyproject.toml, then: uv lock
uv lock --upgrade              # bump every dependency
git add -A                     # Nix only sees tracked files
pytest && ty check              # fast, in the shell
fmt && check                   # ruff (treefmt), ty, pytest, uv-lock, version, docs
```

`UV_NO_SYNC=1`: uv edits the lock only and never creates `.venv` (`uv run`
uses the Nix venv). A new command is a `[project.scripts]` entry; the flake
turns each one into `apps.<system>.<name>` and a binary in
`packages.default`, and it must answer `--version` (add
`_version: VersionOption = None` to the command).

## Checks

| Check | Fails when |
| --- | --- |
| `python-pytest` | a test fails (runs against the installed package) |
| `python-ty` | a type error or warning |
| `python-uv-lock` | `uv.lock` is stale against `pyproject.toml` |
| `python-version` | `pyproject.toml` is not `<major>.<minor>.0` of `ci.yml` |
| `treefmt` | a ruff lint error (Astral's default rules) or unformatted file, and the Nix linters |
| `lock-sync`, `documentation`, `slides` | from org-pkgs |

## VM test

`vm-tests/cli-smoke.nix` installs the package in an offline NixOS VM and runs
every command; `python-cli` (generated by org-pkgs) checks each command's
`--version` and `--help`. They never run in CI; run them by hand:

```sh
vm-test --all --remote --rebuild        # on the remote builder
vm-test cli-smoke                       # one test, local KVM
```

## Updating

nixpkgs and uv2nix come from external-systems/pkgs:

```sh
nix flake update org-pkgs && sync-locks   # one commit
```

CI (`ci / flake-check`) runs `nix flake check` on every PR; on `main` it
deploys this site to GitHub Pages and tags a `0.2.<commits>` release; the
Nix package built from that commit reports the same version.
